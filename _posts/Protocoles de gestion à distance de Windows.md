Les serveurs Windows peuvent être gérés localement à l'aide des tâches d'administration du Gestionnaire de serveur (Server Manager) sur des serveurs distants. La gestion à distance (remote management) est activée par défaut à partir de Windows Server 2016. La gestion à distance est un composant des fonctionnalités de gestion du matériel Windows qui gèrent le matériel du serveur localement et à distance. Ces fonctionnalités comprennent un service qui implémente le protocole WS-Management, des diagnostics et un contrôle du matériel par le biais de contrôleurs de gestion de la carte mère (baseboard management controllers), ainsi qu'une API COM et des objets de script qui nous permettent d'écrire des applications qui communiquent à distance via le protocole WS-Management.

Les principaux composants utilisés pour la gestion à distance de Windows et des serveurs Windows sont les suivants :

- Protocole de bureau à distance (`RDP`)
- Gestion à distance Windows (`WinRM`)
- Instrumental de gestion Windows (`WMI`)

## RDP

Le [Protocole de bureau à distance](https://docs.microsoft.com/en-us/troubleshoot/windows-server/remote/understanding-remote-desktop-protocol) (Remote Desktop Protocol, `RDP`) est un protocole développé par Microsoft pour l'accès à distance à un ordinateur exécutant le système d'exploitation Windows. Ce protocole permet de transmettre les commandes d'affichage et de contrôle via l'interface graphique (GUI) de manière chiffrée sur les réseaux IP. Le RDP fonctionne au niveau de la couche application (application layer) dans le modèle de référence TCP/IP, en utilisant généralement le port TCP 3389 comme protocole de transport (transport protocol). Cependant, le protocole sans connexion (connectionless) UDP peut également utiliser le port 3389 pour l'administration à distance.

Pour qu'une session RDP soit établie, le pare-feu réseau (network firewall) et le pare-feu du serveur doivent tous deux autoriser les connexions depuis l'extérieur. Si la [Traduction d'adresse réseau](https://en.wikipedia.org/wiki/Network_address_translation) (Network Address Translation, `NAT`) est utilisée sur le chemin entre le client et le serveur, comme c'est souvent le cas avec les connexions Internet, l'ordinateur distant a besoin de l'adresse IP publique pour atteindre le serveur. De plus, une redirection de port (port forwarding) doit être configurée sur le routeur NAT en direction du serveur.

Le RDP prend en charge la [Sécurité de la couche de transport](https://en.wikipedia.org/wiki/Transport_Layer_Security) (Transport Layer Security, `TLS/SSL`) depuis Windows Vista, ce qui signifie que toutes les données, et en particulier le processus de connexion, sont protégées sur le réseau par son bon chiffrement. Cependant, de nombreux systèmes Windows n'insistent pas sur ce point et acceptent toujours un chiffrement inadéquat via la [Sécurité RDP](https://docs.microsoft.com/en-us/openspecs/windows_protocols/ms-rdpbcgr/8e8b2cca-c1fa-456c-8ecb-a82fc60b2322). Néanmoins, même avec cela, un attaquant est loin d'être bloqué, car les certificats fournissant l'identité sont simplement auto-signés (self-signed) par défaut. Cela signifie que le client ne peut pas distinguer un certificat authentique d'un faux et génère un avertissement de certificat (certificate warning) pour l'utilisateur.

Le service `Bureau à distance` (Remote Desktop) est installé par défaut sur les serveurs Windows et ne nécessite aucune application externe supplémentaire. Ce service peut être activé à l'aide du `Gestionnaire de serveur` et est configuré par défaut pour n'autoriser les connexions au service qu'aux hôtes disposant d'une [Authentification au niveau du réseau](https://en.wikipedia.org/wiki/Network_Level_Authentication) (Network Level Authentication, `NLA`).

## WinRM

La Gestion à distance Windows (Windows Remote Management, `WinRM`) est un protocole simple de gestion à distance intégré à Windows et basé sur la ligne de commande. WinRM utilise le Protocole d'accès aux objets simple (Simple Object Access Protocol, `SOAP`) pour établir des connexions avec des hôtes distants et leurs applications. Par conséquent, WinRM doit être explicitement activé et configuré à partir de Windows 10. WinRM s'appuie sur les ports `TCP` `5985` et `5986` pour la communication, le dernier port `5986 utilisant HTTPS`, car les ports 80 et 443 étaient auparavant utilisés pour cette tâche. Cependant, comme le port 80 était principalement bloqué pour des raisons de sécurité, les ports plus récents 5985 et 5986 sont utilisés aujourd'hui.

Un autre composant qui convient à WinRM pour l'administration est le Shell distant Windows (Windows Remote Shell, `WinRS`), qui nous permet d'exécuter des commandes arbitraires sur le système distant. Le programme est même inclus par défaut sur Windows 7. Ainsi, avec WinRM, il est possible d'exécuter une commande à distance sur un autre serveur.

Des services tels que les sessions à distance utilisant PowerShell et la fusion des journaux d'événements nécessitent WinRM. Il est activé par défaut à partir de la version `Windows Server 2012`, mais il doit d'abord être configuré pour les versions de serveur et les clients plus anciens, et les exceptions de pare-feu nécessaires doivent être créées.

## WMI

L'Instrumental de gestion Windows (Windows Management Instrumentation, `WMI`) est l'implémentation de Microsoft et aussi une extension du Modèle d'information commun (Common Information Model, `CIM`), une fonctionnalité de base de la norme de Gestion d'entreprise basée sur le Web (Web-Based Enterprise Management, `WBEM`) pour la plateforme Windows. WMI permet un accès en lecture et en écriture à presque tous les paramètres des systèmes Windows. Naturellement, cela en fait l'interface la plus critique de l'environnement Windows pour l'administration et la maintenance à distance des ordinateurs Windows, qu'il s'agisse de PC ou de serveurs. L'accès à WMI se fait généralement via PowerShell, VBScript ou la Console d'instrumentation de gestion Windows (Windows Management Instrumentation Console, `WMIC`). WMI n'est pas un programme unique mais se compose de plusieurs programmes et de diverses bases de données, également appelées dépôts (repositories).

---
