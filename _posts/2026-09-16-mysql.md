`MySQL` est un système de gestion de base de données relationnelle (SGBDR) SQL open-source développé et maintenu par Oracle. Une base de données est simplement une collection structurée de données organisées pour en faciliter l'utilisation et la récupération. Le système de base de données peut traiter rapidement de grandes quantités de données avec une haute performance. Au sein de la base de données, le stockage des données est effectué de manière à occuper le moins d'espace possible. La base de données est contrôlée à l'aide du [langage de base de données SQL](https://www.w3schools.com/sql/sql_intro.asp). MySQL fonctionne selon le `principe client-serveur` et se compose d'un serveur MySQL et d'un ou plusieurs clients MySQL. Le serveur MySQL est le système de gestion de base de données à proprement parler. Il s'occupe du stockage et de la distribution des données. Les données sont stockées dans des tables avec différentes colonnes, lignes et types de données. Ces bases de données sont souvent exportées ou sauvegardées sous la forme d'un unique fichier `.sql`, par exemple `wordpress.sql`.

#### Clients MySQL

Les clients MySQL peuvent récupérer et modifier les données en utilisant des requêtes structurées adressées au moteur de la base de données. L'insertion, la suppression, la modification et la récupération des données se font à l'aide du langage de base de données SQL. Par conséquent, MySQL est adapté à la gestion de nombreuses bases de données différentes auxquelles les clients peuvent envoyer plusieurs requêtes simultanément. Selon l'utilisation de la base de données, l'accès est possible via un réseau interne ou l'Internet public.

L'un des meilleurs exemples d'utilisation d'une base de données est le CMS WordPress. WordPress stocke tous les articles créés, les noms d'utilisateur et les mots de passe dans sa propre base de données, qui n'est accessible que depuis le localhost. Cependant, comme expliqué plus en détail dans le module [Introduction aux applications Web](https://academy.hackthebox.com/course/preview/introduction-to-web-applications), il existe également des structures de bases de données qui sont réparties sur plusieurs serveurs.

#### Bases de données MySQL

MySQL est idéal pour des applications telles que les `sites web dynamiques`, où une syntaxe efficace et une grande vitesse de réponse sont essentielles. Il est souvent associé à un système d'exploitation Linux, à PHP et à un serveur web Apache, et est également connu dans cette combinaison sous le nom de [LAMP](https://en.wikipedia.org/wiki/LAMP_\(software_bundle\)) (Linux, Apache, MySQL, PHP), ou, lors de l'utilisation de Nginx, de [LEMP](https://lemp.io/). Dans un hébergement web avec une base de données MySQL, celle-ci sert d'instance centrale dans laquelle le contenu requis par les scripts PHP est stocké. Parmi ceux-ci, on trouve :

|||||
|---|---|---|---|
|En-têtes|Textes|Balises méta|Formulaires|
|Clients|Noms d'utilisateur|Administrateurs|Modérateurs|
|Adresses e-mail|Informations utilisateur|Permissions|Mots de passe|
|Liens externes/internes|Liens vers des fichiers|Contenus spécifiques|Valeurs|

Des données sensibles telles que les mots de passe peuvent être stockées en clair par MySQL ; cependant, elles sont généralement chiffrées au préalable par les scripts PHP à l'aide de méthodes sécurisées telles que le `chiffrement à sens unique` (`One-Way-Encryption`).

#### Commandes MySQL

Une base de données MySQL traduit les commandes en interne en code exécutable et exécute les actions demandées. L'application web informe l'utilisateur si une erreur se produit pendant le traitement, ce que diverses `injections SQL` (`SQL injections`) peuvent provoquer. Souvent, ces descriptions d'erreurs contiennent des informations importantes et confirment, entre autres, que l'application web interagit avec la base de données d'une manière différente de celle prévue par les développeurs.

L'application web renvoie les informations générées au client si les données sont traitées correctement. Ces informations peuvent être des extraits de données d'une table ou des enregistrements nécessaires pour un traitement ultérieur avec des connexions, des fonctions de recherche, etc. Les commandes SQL peuvent afficher, modifier, ajouter ou supprimer des lignes dans les tables. De plus, SQL peut également modifier la structure des tables, créer ou supprimer des relations et des index, et gérer les utilisateurs.

`MariaDB`, qui est souvent associé à MySQL, est un fork du code original de MySQL. Cela s'explique par le fait que le développeur principal de MySQL a quitté la société `MySQL AB` après son acquisition par `Oracle` et a développé un autre système de gestion de base de données SQL open-source basé sur le code source de MySQL, qu'il a appelé MariaDB.

## Configuration par défaut

La gestion des bases de données SQL et de leurs configurations est un vaste sujet. Il est si vaste que des professions entières, telles qu'`administrateur de base de données`, ne s'occupent presque que de bases de données. Ces structures deviennent très rapidement volumineuses et leur planification peut devenir compliquée. Entre autres, la gestion de bases de données est une compétence essentielle pour les `développeurs de logiciels` mais aussi pour les `analystes en sécurité de l'information`. Couvrir ce domaine entièrement dépasserait le cadre de ce module. ## Paramètres dangereux

De nombreux éléments peuvent être mal configurés avec MySQL. Nous pouvons consulter plus en détail la [référence MySQL](https://dev.mysql.com/doc/refman/8.0/en/server-system-variables.html) pour déterminer quelles options peuvent être définies dans la configuration du serveur. Les principales options pertinentes pour la sécurité sont :

|**Paramètres**|**Description**|
|---|---|
|`user`|Définit l'utilisateur sous lequel le service MySQL s'exécutera.|
|`password`|Définit le mot de passe pour l'utilisateur MySQL.|
|`admin_address`|L'adresse IP sur laquelle écouter les connexions TCP/IP sur l'interface réseau administrative.|
|`debug`|Cette variable indique les paramètres de débogage actuels.|
|`sql_warnings`|Cette variable contrôle si les instructions INSERT sur une seule ligne produisent une chaîne d'information en cas d'avertissements.|
|`secure_file_priv`|Cette variable est utilisée pour limiter l'effet des opérations d'importation et d'exportation de données.|

Les paramètres `user`, `password` et `admin_address` sont pertinents pour la sécurité car les entrées sont faites en clair. Souvent, les droits pour le fichier de configuration du serveur MySQL ne sont pas attribués correctement. Si nous obtenons un autre moyen de lire des fichiers ou même un shell, nous pouvons voir le fichier ainsi que le nom d'utilisateur et le mot de passe du serveur MySQL. S'il n'y a pas d'autres mesures de sécurité pour empêcher un accès non autorisé, l'ensemble de la base de données et toutes les informations des clients existants, les adresses e-mail, les mots de passe et les données personnelles peuvent être consultés et même modifiés.

Les paramètres `debug` et `sql_warnings` fournissent une sortie d'information verbeuse en cas d'erreurs, ce qui est essentiel pour l'administrateur mais ne devrait pas être vu par d'autres. Ces informations contiennent souvent du contenu sensible, qui pourrait être détecté par essais et erreurs pour identifier d'autres possibilités d'attaque. Ces messages d'erreur sont souvent affichés directement sur les applications web. Par conséquent, les injections SQL pourraient être manipulées au point de faire exécuter des commandes système par le serveur MySQL. Ceci est discuté et montré dans les modules [Principes fondamentaux de l'injection SQL](https://academy.hackthebox.com/course/preview/sql-injection-fundamentals) et [Les essentiels de SQLMap](https://academy.hackthebox.com/course/preview/sqlmap-essentials).

## Prise d'empreinte du service

Néanmoins, c'est loin d'être l'une des meilleures pratiques, et nous pouvons toujours trouver des bases de données que nous pouvons atteindre. Souvent, ces paramètres n'étaient censés être que temporaires mais ont été oubliés par les administrateurs. Cette configuration de serveur pourrait également être utilisée comme solution de contournement en raison d'un problème technique. Le `schéma d'information` (`information_schema`) est également une base de données qui contient des métadonnées. Certaines des commandes que nous devrions mémoriser et noter pour travailler avec les bases de données MySQL sont décrites dans le tableau ci-dessous.

|**Commande**|**Description**|
|---|---|
|`mysql -u <user> -p<password> -h <IP address>`|Se connecter au serveur MySQL. Il ne doit **pas** y avoir d'espace entre l'option '-p' et le mot de passe.|
|`show databases;`|Afficher toutes les bases de données.|
|`use <database>;`|Sélectionner l'une des bases de données existantes.|
|`show tables;`|Afficher toutes les tables disponibles dans la base de données sélectionnée.|
|`show columns from <table>;`|Afficher toutes les colonnes de la table sélectionnée.|
|`select * from <table>;`|Afficher tout le contenu de la table souhaitée.|
|`select * from <table> where <column> = "<string>";`|Rechercher la `chaîne` de caractères nécessaire dans la table souhaitée.|
